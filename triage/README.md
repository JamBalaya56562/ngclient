# ngclient triage

PRを作るためのブランチではなく、現在の判断と証拠の入口を保存する。

| 読むもの                                                   | 用途                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| [tasks.md](tasks.md)                                       | 現在の状態・次の判断・依存・重複回避。正本はここだけ    |
| [verification.md](verification.md)                         | 現在のPRと公開待ち作業の検証記録へ辿る                  |
| [移管18件の索引](2026-11-15-duplicati-ngclient-records.md) | SHA・agentId・赤の種類・未実施・レビュー訂正            |
| [pr-drafts/](pr-drafts/)                                   | 未公開の本文原文。公開前にIssue全体の範囲と記録を再確認 |
| [completed.md](completed.md)                               | 完了・廃止IDの最小索引。IDを再利用しない                |

## 検索

通常は`rg -n "NGT-050|#637" triage`のように台帳・索引・本文を検索する。`triage/.ignore`は大量の一次記録がある`evidence/`だけを通常のrg検索から除く。Gitの追跡や保存には影響しない。

一次記録が必要なときだけ、例として`rg --no-ignore -n "a0656a2392a87bbaf" triage/evidence/2026-11-15-duplicati-ngclient`で範囲を指定する。巨大なJSONLには原文があるため、まず索引からagentIdやファイルを絞る。

## 更新

1. GitHubとjjでIssue・PR・main・準備済み差分を照合し、tasks.mdの該当行を更新する。jj/ghはmiseの実体を直接呼ぶ。
2. 事実には実行結果・公開コメント・固定SHAを添える。検証済み／ドキュメント根拠／推測／未検証を分ける。
3. 完了した作業はcompleted.mdへ最小限を移す。古い候補一覧・件数・「次へ」の連鎖を新しい文書へ複製しない。
4. 進行中の作業の証拠・未実施・失敗した初回レビューは残す。経過の再読が必要ならGit履歴を参照し、台帳の現在地と混同しない。
5. このブランチを実装の親にしない。公開や既存ブランチの更新は個別の依頼に従う。
