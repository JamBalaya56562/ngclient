# ngaxにだけある機能の棚卸し（2026-11-17）

利用者の方針: ngaxを直すより、ngclientを充実させてngaxを廃止する。その前にngclientへ足すべき機能を洗い出した。

- 比較対象: duplicati master `46aabe2c6716`の`Duplicati/Server/webroot/ngax`と、ngclient upstream/main `ae54d73bf1e5`（0.0.250、2026-11-16）の`projects/ngclient/src/app`。ngclientの作業コピーは0.0.250の古い版なので、`git show`/`git grep upstream/main`で読んだ。
- 方法: 画面ごとの比較はサブエージェント（読み取りのみ）。主な項目は下のコマンドで追試した。

## サブエージェントの報告だけのもの（未追試）

- 保存時の確認（`EditBackupController.js`）: 弱いパスフレーズ:352、自動生成パスフレーズの控え:367、パスフレーズ・暗号化の変更:401/:410、暗号化なし:437、ソースパスの相対・不存在・ファイルかフォルダーか:146-171。ngclientでは`backup/backup.state.ts`が宛先・ソース・フォーム妥当性だけを確認し、強度メーターと「パスワードを控えて」の表示はある。文言の検索で該当なし（`weak|autogenerated|no encryption`で無関係の2件だけ）。
- バックアップなしのコマンドライン: ngaxの`/commandline`ルート（メニューからのリンクなし、URL直打ちのみ）。ngclientは`backup/:id/commandline`だけ。ngaxは`/backup/{id}/export-argsonly?export-passwords=true`で引数を作り、ngclientはバックアップのオブジェクトから作る。

## 対象外と判断したもの

- `/api/folder-context`（`scripts/services/BackupList.js:64`）: サーバーにエンドポイントがない（同上）。
- テーマのサーバー保存（`/uisettings/ngax`）: NGT-091 / #744で対応中。
